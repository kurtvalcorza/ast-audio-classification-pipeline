## Conformance notes

- **Sound-event workshop (`WORKSHOP`, NOTEBOOK_SPEC 2.2, added 2026-09-27):** the notebook is generated outside this repository (`generated_from` records the base revision and the SHA-256 of each carried file) and does not use `tools/build_notebook.py`. `tools/validate_release_assets.py` checks its metadata, that no outputs are persisted, that every code cell is plain Python, that each carried file matches its `CARRIED_HASHES` digest, that the carried `ast_reference/` modules, AST manifest and code licence equal `src/ast_audio_classification_pipeline/`, `weights/ast-audioset/dimer-base-manifest.json` and `LICENSE`, that the carried `source.json` agrees with the metadata, and that the carried ESC-50 metadata CSV and LICENSE are the files the sample manifest pins (`karolpiczak/ESC-50@33c8ce9`). Its design specification is `../docs/sound-event-classification-workshop-spec.md`.

- **Standalone and parity:** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` verify that the carried package modules, stage runner, lock, manifest and licence equal the repository files, that `CARRIED_HASHES` is correct, and that the generated notebook bytes match `tools/build_notebook.py` output.
- **Run-all:** one pass, no restart. The default path checks the runtime, verifies the carried files, builds the isolated environment, stages and verifies `MIT/ast-finetuned-audioset-10-10-0.4593` at revision `f826b80d28226b62986cc218e5cec390b1096902`, checks the installed versions against the lock, demonstrates the unchanged independent-sigmoid AudioSet head, builds and validates the dataset (refusing duplicate clips), performs the seeded split, re-head, freeze, untrained-head and training-majority baselines, five-epoch cached-feature fine-tune and adapter export, held-out evaluation and unseen prediction in a fresh process, reload parity in another fresh process, and the provenance export.
- **Dataset contract:** the default generated records use `io.github.kurtvalcorza.dataset.audio.waveform-classification.v1`; each generated clip gets a seeded per-record variation (speed, time shift, gain, noise floor), so the 24 clips are 24 distinct waveforms. The optional dataset upload is one ZIP of `geophony/`, `biophony/`, and `anthrophony/` folders (at the top level or inside one enclosing folder; `__MACOSX/` and dot-files skipped), at least two 16 kHz PCM WAV files per class, 0.025–10.24 seconds per clip, no duplicate clips, at most 100 files, 64 MiB compressed, and 256 MiB expanded. Members are inspected and decoded in memory; the archive is not extracted. Refusals name the member and the fix.
- **Evaluation:** base AudioSet inference is still not measurable without ontology-aligned labels. The adapted path evaluates six held-out clips with multiclass accuracy, macro-F1, per-class statistics and a confusion matrix, against a majority baseline fitted on the training labels. Scores are uncalibrated softmax scores and the decision rule is argmax. This small synthetic result is a sample-sanity check, not a real-world benchmark.
- **Artifact:** `ast-audio-adapter-v1.pt` stores only the 3,843-parameter classifier head plus ordered classes, adaptation configuration, and exact base lineage. Reload uses `torch.load(..., weights_only=True)` over a fresh pinned base-model instance.
- **Outputs:** each run writes, under `outputs/ast_audio_classification/<run id>/outputs/`, an input manifest, split record, pre-adaptation and training records, evaluation report, unseen prediction, rank-ordered CSV, reload-parity record, result/provenance JSON, and the adapter artifact.
- **Release boundary:** one hosted Colab T4 default-path run of the isolated-environment revision is recorded (one pass, no restart, 0 errors). The notebook remains Candidate until the Kaggle, BYOD and activity runs are recorded and an integrator explicitly approves promotion.
