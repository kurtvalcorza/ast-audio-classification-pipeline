## Conformance notes

_Requirement identifiers in these notes (for example `ST1`, `PAR3`, `DAT24`, `EVAL21`) are the NOTEBOOK_SPEC 1.1 numbering they were written against; NOTEBOOK_SPEC 2.0 renumbered its sections and the pull request that migrated this repository reports conformance against the 2.0 pre-flight checklist (§26) and report format (§30)._

- **Standalone carrier (ST1–ST6):** the primary path performs no clone, repository install, or repository import. Section 2 is `src/ast_audio_classification_pipeline/pipeline.py` verbatim (tagged `metadata.dimer.embedded_module`; the only rewrite makes the default weights directory working-directory-relative), Section 3 carries the model identity and the 4-file SHA-256 manifest inline (346 MB total) and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins. `metadata.dimer.generated_from` records the repository, the generating revision, the module's SHA-256, and the generator version.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried module, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Role stages:** `validate_inputs` (DAT24) writes `outputs/ast_audio_classification_input_manifest.json` with the schema, ceilings, per-clip identifier, sample count, duration, peak amplitude, `will_resample`/`will_truncate` flags, verdict, and one recorded rejection finding; it applies the checks through the same private function `predict` uses, so the two cannot diverge. `evaluation_report` (EVAL21) writes `outputs/ast_audio_classification_evaluation_report.json`, whose verdict is **always** `not-measurable` (EVAL9): the repository ships no metric helper, and the report names what labelled audio and which metrics (AudioSet-convention mAP plus per-label precision/recall at a caller-chosen threshold) would make the task measurable.
- **Model acquisition** goes through the carried module, never the notebook: `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh clone lacks, at the pinned revision, `verify_snapshot` re-hashes every entry, and `from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files (`local_files_only=True`, `trust_remote_code=False`; the notebook never calls `huggingface_hub`).
- The default sample is a synthetic 3 s, 440 Hz sine tone generated in code at 16 kHz (no download, no ground truth); its ranking is sanity evidence for the input contract, feature extraction and forward pass, not a correctness or benchmark claim. The smoke observation quoted from the model card (`Sine wave` first at 0.84) is one observation, not a calibration point.
- Score semantics: every `score` is an independent sigmoid, described as uncalibrated and not a probability; no threshold is shipped and the caller owns per-label thresholds and calibration; exported top-k scores keep their rank ordering in both JSON and CSV.
- Ceilings (`SAMPLE_RATE` 16 kHz, `MAX_AUDIO_SECONDS` 10.24 s window, `MAX_INPUT_SECONDS` 120 s, `NUM_LABELS` 527) are printed before the model runs; a clip longer than the window is flagged `will_truncate` in the input manifest and announced before inference, and the result carries `truncated: True`; a clip above `MAX_INPUT_SECONDS` is rejected by the validation stage.
- `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; BYOD decodes PCM WAV with the standard-library `wave` module because no audio decoder beyond `torchaudio.functional.resample` is pinned.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the
  clean-runtime execution requirement; a release review must confirm that a recorded clean run in
  `docs/release-verification.md` matches the notebook revision under review before the status is
  promoted to `Release-grade`.
